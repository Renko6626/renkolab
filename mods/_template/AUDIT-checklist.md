# 对抗审计 checklist —— 手写机器码 / hook 产出必过

> 用法：**独立**跑一遍，姿态是「默认我们写错了，去二进制找证伪证据」。
> 不是复述设计，是攻击它。逐条给出**地址级证据**，不接受「应该」「大概」。

## A. ABI / 栈平衡（★ 最易错，历史上唯一的真 BLOCKER 出在这）

- [ ] cave 调用的**每一个**引擎函数，查明调用约定：结尾是 `RET imm`（stdcall，callee 清栈）
      还是 `RET`（cdecl，caller 清栈）？逐个列出地址与结论。
- [ ] 交叉验：**引擎自己**怎么调这个函数？调用点后面有没有 `add esp`？
      有 `add esp` = cdecl；没有 = stdcall。这条比读函数尾更硬。
- [ ] 对每个 stdcall 调用，确认 cave 里**没有**多余的 `add esp`。
      （典型症状：ESP 抬高 → `pop esi/edi` 读到栈帧局部 → 跨调用持有的寄存器被破坏 → 崩在别处。）
- [ ] 被调函数会破坏哪些寄存器？cave 跨调用持有的值是否已保存？
- [ ] cave 自己的返回约定（`ret` vs `ret imm`）与被 patch 的调用点匹配？
- [ ] FPU：压栈顺序、栈深度平衡（进出 cave 时 FPU 栈是否等深）？

## B. 写入点

- [ ] 每个 `expected` 原字节串与目标 exe 实际字节**逐字节**核对过？
- [ ] 相对 / 绝对表达式用对了？数据指针表槽 = `<expr>`（绝对），
      调用/跳转 = `[expr]`（相对 rel32）。
- [ ] 目标地址是否落在只读节（`.rdata`）？thcrap 会在 apply 时设页可写，但要确认写的是对的位置。
- [ ] 被重指的槽在零售流程中**确实不被用到**（或用到的后果已评估）？
      给出证据，不要只说「应该没人用」。

## C. 偏移与内存安全

- [ ] 每个结构偏移都能回指 `engine/` 里的一手文档（有地址）？
- [ ] 池 / 数组的算式（base + idx\*stride）与一手文档一致？有没有多减少加一？
- [ ] 空指针路径：被重指的槽若原值为 0，引擎是否会 `call 0`？找到派发点确认它有 `if (ptr) call; else ...`。
- [ ] 释放后使用（UAF）：cave 若自释放，返回值语义是否让调用方**不再碰**该槽？

## D. 量纲 / 常识关

- [ ] 每个「字段 == 常量」的判断，查过该字段在**真实数据文件**里的取值分布吗？
      （历史教训：把 0x21 当布尔 `==2`，实为按角色 {0,1,2,4}；把 slot+0x60 当角度，实为速度。）
- [ ] 数值量级合理吗？（伤害/帧数/半径 与游戏实际表现对得上？）
- [ ] 结论与游戏内实际可观察行为冲突时，**先怀疑自己的映射**。

## E. 收尾

- [ ] 汇编后**比对反汇编**，确认生成的机器码就是设计的那些指令。
- [ ] 有可还原的补丁（能一键关掉）？
- [ ] **游戏内实跑**验证（崩溃 / 坐标 / FPU 栈平衡）——
      静态审计通过 ≠ 能跑。未实跑的产出必须在 README 里明写。

## 结论格式

每条 claim 标 **CONFIRMED（一手，附地址）/ REFUTED（附反证）/ OPEN（说清缺什么）**。
只解开了某个分支，别写成「整个问题已解」。
